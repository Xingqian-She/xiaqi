# 二维轴向 RoPE

`AxialRoPE2D` 接收形状为 `[B, H, 1 + n², head_dim]` 的 Q/K，其中 `H` 是注意力头数。序列首位是 CLS，后续棋盘点按行展开。每层在联合 QKV 投影之后、计算注意力分数之前旋转 Q/K。V 直接参与注意力加权。 [实现代码](axial_rope_2d.py)

## 棋盘坐标与旋转频率

数组行、列从 0 开始。棋盘边长 `n` 取正奇数，令 `h = (n−1)/2`，交叉点坐标为 `(x, y) = (列−h, 行−h)`，向右、向下为正。中心点为 `(0, 0)`。9、13、19 路棋盘每轴坐标分别为 `−4…4`、`−6…6`、`−9…9`。

每个头的前半通道使用列坐标 `x`，后半通道使用行坐标 `y`。两个相邻通道组成一个旋转平面，因此 `head_dim` 取 4 的倍数。每轴有 `m = head_dim / 4` 对通道，第 `j` 对的频率为 `theta^(−j/m)`，`j` 从 0 开始，`theta` 默认为 `100`。每对通道的旋转角度等于坐标乘以频率，负角表示反向旋转。不同尺寸始终以一格为单位，沿用同一组频率。 [二维 axial RoPE 论文](https://arxiv.org/html/2403.13298v2#S3.SS2)

## CLS 与注意力点积

CLS 在每对相邻通道上固定旋转 `π`（180°），数学上对应 `R_CLS = −I`。棋盘中心取零相位。每轴首对通道的频率为 `1`，整数棋盘坐标对应的相位在模 `2π` 下与 `π` 不同，因此 CLS 与任一棋盘点使用不同的旋转矩阵。

令 `i`、`j` 表示棋盘坐标，`R(i)` 表示坐标 `i` 的旋转矩阵。旋转前的 `q_i` 和 `k_j` 分别变为 `R(i) q_i` 和 `R(j) k_j`。由 `R(i)ᵀR(j) = R(j−i)` 可知，位置只通过相对位移进入两个棋盘点的点积。

| 查询 | 键 | 旋转后的点积 |
| --- | --- | --- |
| 棋盘点 `i` | 棋盘点 `j` | `q_iᵀ R(j−i) k_j` |
| CLS | 棋盘点 `j` | `−q_CLSᵀ R(j) k_j` |
| 棋盘点 `i` | CLS | `−q_iᵀ R(i)ᵀ k_CLS` |
| CLS | CLS | `q_CLSᵀ k_CLS` |

单独平移棋盘坐标仍可能改变 CLS 与棋盘点之间的点积。9 路棋盘上，每轴最多相隔 8 格，19 路棋盘上可相隔 18 格。跨尺寸棋力仍需实测。

## 测试

构建好项目的 `dev` 镜像后，在仓库根目录运行：

```sh
docker compose run --rm --no-deps --pull never -T dev python -m unittest -v src.core.model.positional_encoding.axial_rope_2d_test
```

[单元测试](axial_rope_2d_test.py)覆盖：

- CLS 半圈、棋盘中心零相位、四个方向的旋转，以及默认和自定义 `theta` 下每轴的频率。
- 9×9、13×13、19×19 棋盘上，棋盘点 Q/K 的点积符合相对位移公式。
- 多批次、多头的非连续 Q/K 保持原形状和范数，反向梯度与解析值一致；旋转表不写入 `state_dict`。
- 拒绝不合法的构造参数及 Q/K 形状或数据类型。
- CUDA 可用时，验证旋转表随模块移动，保持输入的 `float16` 类型，且结果与 CPU 在容差内一致。CUDA 不可用时跳过这项。
